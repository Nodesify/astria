# 1.0.0 readiness

Status: DRAFT — this is the contract the maintainer signs up to when 0.8.0 ships as 1.0.0.
Ticket: GPF-2. Current package version: 0.8.0 (`package.json:3`). Current graph DB schema version: **6** (`crates/graphify-core/src/db.rs:151-158`).

Every freeze claim below cites the artifact it is read from. Undecided points are listed in **Open questions** and are decided in PR review, not before.

---

## 1. What freezes at 1.0.0

### 1.1 CLI commands and flags — FROZEN

The frozen surface is exactly the Usage block in `README.md:64-92`, defined in code by `packages/graphify-cli/src/index.ts:35-199`:

`run`, `update`, `watch`, `explain`, `query`, `path`, `map`, `affected`, `stats`, `export`, `cluster-only`, `merge`, `diff`, `history`, `mcp`, `tree`, `wiki`, `prs`, `add`, `status`, `install`, `uninstall`, `hook`.

What the freeze means:

- No existing command is renamed or removed in 1.x.
- Existing flags keep their name, position, meaning, and default value (e.g. `query --depth` stays 2, `--budget` stays 2000, `--graph` stays `.` — `packages/graphify-cli/src/index.ts:70-80`; `watch --debounce` stays 3000 ms — `index.ts:59`).
- `export --format` keeps `json` as its default (`packages/graphify-cli/src/index.ts:116-122`; asserted by `packages/graphify-cli/src/__tests__/cli.test.ts:92`).
- Adding new commands and new flags is allowed; it cannot break an existing invocation.

### 1.3 Graph DB schema version — FROZEN AT v6

`_meta.schema_version` is `6` in every graph written by 0.8.0: the last step of the sequential migration chain sets `'6'` (`crates/graphify-core/src/db.rs:151-158`), and the unit test pins it (`db.rs:258`: `assert_eq!(version, "6")`).

The v6 table set (from `SCHEMA_V1`/`SCHEMA_V2`/`SCHEMA_V5`/`SCHEMA_V6` plus the v3/v4 `ALTER TABLE`s, `db.rs:4-100`):

- `nodes` (incl. `signature` since v3)
- `edges` (incl. `source_line` since v4)
- `extraction_cache`, `file_manifest`, `pipeline_runs`, `query_history`, `_meta`
- `communities` (v2), `node_embeddings` (v5), `query_pairs` (v6)

Contract: anything reading `db.sqlite` (the MCP server, the CLI, external tools reading `.graphify/`) can rely on this table set at schema version 6. Columns and tables are added only by appending a new versioned migration (v7, v8, …) to the chain — existing v6 rows keep their columns and meaning.

### 1.4 Output shape of `query` / `explain` / `path` — FROZEN (it is text, not JSON)

Correction to the ticket's premise: in 0.8.0 these three commands emit **plain text** — there is no `--json` flag anywhere in the CLI (`grep` over `packages/graphify-cli/src` finds JSON only in `export` and the `gh pr` calls in `prs.ts`). The frozen contract is therefore the line grammar below. The JSON artifact that *does* exist is `export --format json`, frozen separately in 1.5.

**`query`** (formatting: `crates/graphify-query/src/lib.rs:547,618,782`; CLI renderer `packages/graphify-cli/src/commands/query.ts:24-30`):

```
Traversal: {BFS|DFS} depth={n}[ directed] | Start: {seed labels} | {n} nodes found

NODE {label} [id={id} src={file}:{line} community={n}]
  sig: {signature up to 140 chars}          # or:   summary: {docstring up to 200 chars}
EDGE {source} --{relation} [{confidence}]--> {target}[@{file}:{line}]
... (showing nodes {a}-{b} of {n}; edges follow)
(continuation: re-run with cursor {n} for the next nodes)
# graph built at {timestamp}                # CLI only (query.ts:29)
({n} nodes, {m} edges)                      # MCP only (crates/graphify-mcp/src/lib.rs:122)
```

**`explain`** (CLI renderer `packages/graphify-cli/src/commands/explain.ts:10-27`; data from `explain_with_neighbors` and its result structs, `crates/graphify-query/src/lib.rs:1115-1197`; MCP variant `crates/graphify-mcp/src/lib.rs:137-156`):

```
Node: {label}
  ID: {id}
  File: {file}:{line}
  Community: {n}

Connections ({count}):
  --> {neighbor label} [{relation}] [{confidence}] ({neighbor file}:{line})
  ... and {n} more                          # when neighbors are truncated at 20
```

**`path`** (formatting `crates/graphify-query/src/lib.rs:949-988`; MCP wrapper `crates/graphify-mcp/src/lib.rs:197`):

```
Shortest path ({hops} hops):
  {label} --{relation} [{confidence}]--> {label}     # one line per hop
```

Not-found shapes are frozen too: `No matching node for '{q}'. Did you mean: …?`, `No path found.` (`lib.rs:949-971`), and query's `No matching nodes found. Did you mean: …?` (`lib.rs:756-765`).

**Programmatic result objects** are frozen as defined by the napi structs `QueryResultJs` (`text`, `nodeCount`, `edgeCount`, `nextCursor`, `graphBuiltAt`), `PathResultJs` (`found`, `hops`, `text`), `ExplainResultJs`, `EdgeInfoJs` (`crates/graphify-napi/src/lib.rs:34, 52, 59, 69`, constructed at `lib.rs:311-317, 365-369, 384-404`). Caveat: the checked-in `packages/graphify-cli/graphify.node.d.ts` lags these (no `nextCursor`/`graphBuiltAt`/`sourceLine`); the Rust definitions are authoritative, and aligning the `.d.ts` is pre-1.0 cleanup.

### 1.5 `export --format json` (`graph.json`) — FROZEN

Top-level shape `{ "nodes": [...], "edges": [...] }`; node keys `id, label, file_type, source_file, source_line, docstring, community, signature`; edge keys `source, target, relation, confidence, confidence_score, source_file` (`crates/graphify-napi/src/pipeline.rs:500-575`). A real 0.8.0 self-export matching this exactly is captured at `worked/nodesify-graphify/graph.json`. Existing keys keep their name and meaning; new keys are additive.

## 2. Migration policy

- **Schema bump ⇒ migrate in place.** `run`/`update` apply the sequential `version < N` migrations (`crates/graphify-core/src/db.rs:112-159`) automatically on open; 1.x extends the chain forward-only (v7 = append, never rewrite v1-v6, never reset the version counter), so a v6 graph upgrades in place with no rebuild.
- **Removing a CLI flag ⇒ deprecate one minor before removal.** The flag keeps working but prints a deprecation warning for at least one minor release; removal happens no earlier than the following minor. (Whether the window should be two minors — **Open question 3**.)

## 3. Explicitly not frozen

- **Wiki layout** — `.graphify/wiki/` article structure, Obsidian vault/canvas layout (`export_wiki.rs`, `export_obsidian.rs` evolve freely).
- **HTML viewer internals** — `tree.html`, and the `export --format html` standard/large viewers (layout, search, legend, caps).
- **Embedding model choice** — which local model `run --embed` downloads and its dimensions; `node_embeddings.model` is stored per row precisely so it can change.
- **Learned-edge heuristics** — promotion thresholds and hits-based scoring (`promote_learned_edges`, `crates/graphify-query/src/lib.rs:867+`).
- **Prose** — `graph_report.md` text, MCP tool `description` strings and the `initialize` instructions string, token-benchmark wording, community labels, god-node ranking, and output ordering within the frozen line formats.
- **Everything env-var driven** — LLM backends and models (`GRAPHIFY_LLM_*`), `GRAPHIFY_EMBED_CACHE_DIR`, `GRAPHIFY_LLM_CONCURRENCY`.
- **Anything still experimental** — features introduced in a 1.x minor behind a new flag are not covered by this contract until this doc names them.

## 4. Open questions (decide in PR review)

1. Does `update` migrate a v6 graph forward, or does a major schema change force a rebuild? (Current code says forward, in place — see Migration policy — but a future v7 that reshapes existing tables may be cleaner as rebuild; decide when v7 is actually proposed.)
2. Is the MCP tool surface frozen or additive-only at 1.0.0? (Existing names/arguments are frozen either way; the open part is whether *new* tools may ship in 1.x minors.)
3. What is the deprecation window for CLI flags — one minor or two?
