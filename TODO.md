## Enhancements inspired by Graphify

Source: [Graphify 0.9.88–0.9.91 release notes](https://github.com/Graphify-Labs/graphify/blob/v8/CHANGELOG.md), reviewed on 2026-10-16 against Astria's current implementation.

Revised priority after the deeper review: project-aware imports, extraction completeness, confidence-aware clustering, TypeScript receiver resolution, then outcome-based memory. Typed cross-repository calls and interface dispatch follow typed resolution. Fit the smaller improvements (explicit seeds, stable labels, post-merge refresh, parser fingerprints, language overrides, and contextual agent guidance) around that sequence.

- [x] **Explicit query seeds — quick win.** Add `--seed` to the query CLI and equivalent MCP support, passing explicit seeds through the native/query layers. Allow an agent to retrieve graph context around known symbols without relying on keyword ranking. Report unresolved seeds; if all supplied seeds are unresolved, return no match rather than silently switching to keyword seeds. Start in `packages/astria-cli/src/commands/query.ts` and `crates/astria-query/src/lib.rs`.

- [x] **Stable community labels — quick win.** Preserve an existing label when shared nodes form a strict majority of both the previous and current community memberships, rather than requiring identical membership hashes. Handle splits and merges without assigning one old identity ambiguously. Track summary freshness separately so label retention does not imply an old summary is still accurate. Start in `crates/astria-cluster/src/lib.rs` and community enrichment in `crates/astria-napi/src/pipeline.rs`.

- [x] **Post-merge graph refresh — operational improvement.** Add a post-merge Git hook alongside the existing post-commit and post-checkout hooks. Use the existing incremental update path to refresh after merges and pulls, preserving unrelated user hooks. Extend hook installation, removal, status reporting, and documentation together. Start in `packages/astria-cli/src/install/hooks.ts` and `packages/astria-cli/src/commands/hook.ts`.

- [x] **Type-aware receiver resolution — high accuracy priority.** Start with TypeScript constructor parameters, typed class fields, local variables, and inherited members. Resolve calls such as `this.service.save()` through the receiver's declared type and lexical scope, respecting parameter/local shadowing and class ownership. Keep ambiguous or unsupported calls unresolved and preserve the distinction between name/type-derived resolution and compiler-proven facts. Project-aware import resolution should precede or accompany this work. Start in `crates/astria-extract/src/refs.rs` and the extraction metadata feeding it.

- [x] **Typed cross-repository member calls — follows receiver resolution.** Retain receiver type, package/import identity, and member name for unresolved member calls during extraction. Resolve these when repositories are combined, using available identity evidence instead of bare-name coincidence. Refuse ambiguous targets and retract derived links when repository additions, removals, or updates change the evidence. Astria's current global resolver skips `receiver::` targets. Start in `crates/astria-napi/src/global.rs`.

- [x] **Interface dispatch to possible implementations — follows typed resolution.** Connect an interface member to every supported implementation with matching type/member evidence, enabling useful dependency-injection call flows and impact analysis. Represent these as possible implementations, not proven runtime calls; preserve provenance and avoid arbitrary single-target selection. Review extraction, graph relations, query traversal, call-flow output, and affected-node analysis together.

Implementation direction: retain Astria's SQLite publication model, generation-based freshness, evidence levels, and optional embeddings. Borrow the useful behavior without introducing Graphify's JSON merge-healing machinery or speculative cloud/formal-verification features.

## Additional findings from the deeper Graphify review

Reviewed on 2026-10-16 against Graphify's implementation and release history through 0.9.91. These are source-backed opportunities; performance and retrieval gains have not been measured.

- [x] **Project-aware import resolution — highest priority.** Resolve TypeScript `paths` aliases and `baseUrl`, workspace package source entry points, re-export chains, and Node package subpath imports/exports. Start with aliases and workspace entries; prefer authored source where project metadata supports it, and leave ambiguous or unsupported mappings unresolved. Configuration changes must refresh affected bindings even when importing files are unchanged. Start in `crates/astria-extract/src/refs.rs` and `manifest.rs`; upstream reference: `graphify/extractors/resolution.py`.

- [x] **Extraction completeness reporting — high priority.** Record per-file status for complete, partial, unsupported, intentionally skipped, and suspiciously empty extraction, with parser-error locations where available. Distinguish legitimate empty/data-only files from unexpected symbol loss. Surface completeness in reports and MCP results so agents can distinguish missing relationships from incomplete understanding. Start in `crates/astria-extract/src/walkers.rs`, `schema.rs`, and `crates/astria-analyze/src/diagnose.rs`; upstream reference: diagnostic handling in `graphify/extract.py`.

- [x] **Confidence-aware architecture analysis — high priority.** Clustering currently loads unweighted source/target edges despite stored confidence metadata. Apply evidence-aware weighting consistently through clustering and community split/merge passes, and keep learned usage signals distinct from structural architecture. Avoid allowing weak inferred or semantic connections to dominate module boundaries. Determine weights from evidence rather than assuming Graphify's ambiguous-edge multiplier is optimal for Astria. Start in `crates/astria-cluster/src/lib.rs`; upstream reference: `graphify/cluster.py`.

- [x] **Outcome-based memory and actionable reflection — high value.** Extend `reflect` beyond outcome counts and question lists to preferred sources, tentative findings, contested evidence, corrections, and known dead ends. Use cited nodes, correction text, recency weighting, and corroboration; discard references to deleted nodes. Keep experiential lessons separate from structural facts, and review query-pair promotion so repeated unsuccessful exploration does not become authoritative evidence. Start in `crates/astria-napi/src/feedback.rs` and `crates/astria-query/src/learned.rs`; upstream reference: `graphify/reflect.py`.

- [x] **Parser-dependent extraction cache fingerprints — medium priority.** Include relevant grammar dependency versions and extraction rules in a generated extraction fingerprint instead of relying solely on a manually bumped extraction version. Grammar upgrades must invalidate affected cached extraction without invalidating everything for unrelated dependency changes. Start in `crates/astria-extract/src/cache.rs` and `crates/astria-core/src/lib.rs`; upstream reference: `_grammar_fingerprint` in `graphify/cache.py`.

- [x] **Project-specific language mappings — medium priority.** Add a small project-level extension override for ambiguous or custom suffixes, such as `.inc` as PHP or `.tpl` as TypeScript. Validate mappings and consume them consistently in discovery, parser selection, import resolution, watch, and cache identity; changing a mapping must invalidate affected extraction. Build on the shared registry in `crates/astria-core/src/languages.rs`; upstream reference: `graphify/rcfile.py`.

- [x] **Contextual agent guidance — practical improvement.** Replace generic search/read nudges with a few relevant graph symbols, source locations, and a concrete query suggestion when useful evidence is available. Bound lookup time and output size, avoid repetitive noise, and preserve fail-open behavior. Start in `packages/astria-cli/src/commands/hook-guard.ts`; upstream reference: Graphify's context-bearing hook nudges in the 0.9.89 release.
